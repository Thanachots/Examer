# Engine — ข้อตกลงระหว่างหน้า app กับโมเดล

โมเดลจะ**รันในเบราว์เซอร์** (ไม่มี server) หน้า app เรียกโมเดลผ่านจุดเดียวคือ `Pipeline.run()` ใน
[`apps/js/pipeline.js`](../apps/js/pipeline.js) — วิธีเอาโมเดลเข้าเว็บ (Pyodide / เขียนใหม่เป็น JS + ONNX) ยังไม่ได้เลือก
แต่ไม่ว่าจะทำแบบไหน **ผลที่ส่งกลับต้องเป็นรูปแบบในเอกสารนี้** หน้า app จะได้ไม่ต้องแก้

> สถานะ: **ร่าง v0.1** — ตอนนี้ `Pipeline.run()` ยังเป็นโหมดจำลอง (`mockResult()`) ที่ตอบตามรูปแบบนี้
> ถ้าทีมโมเดลจะเปลี่ยนชื่อ/ความหมายฟิลด์ ให้แก้ไฟล์นี้และ `pipeline.js` ใน PR เดียวกัน

## เรียกใช้

```js
const result = await Pipeline.run(file, key);
// file: File      ภาพกระดาษคำตอบ (JPG/PNG)
// key:  string[]  เฉลย 20 ข้อ ("" = ข้อนั้นไม่นับคะแนน)
```

ถ้าตรวจไม่ได้ให้ `throw new Error("ข้อความภาษาไทย")` — หน้า app จะแสดงข้อความนั้นให้ผู้ใช้
เช่น `"หาสี่เหลี่ยมดำ 3 มุมของกระดาษไม่ครบ — ถ่ายใหม่ให้เห็นทั้งแผ่น"`

## ผลที่ส่งกลับ (`Result`)

### ฟิลด์ที่หน้า app ใช้อยู่แล้ว (ต้องมี)

```jsonc
{
  "student_id": "67160328",            // อ่านจากช่องรหัสสีม่วง ("" ถ้าไม่ได้เขียน)

  "dewarp": {                          // ① ตัดขอบ/ปรับภาพ
    "corners": [[x,y],[x,y],[x,y],[x,y]], // มุมกระดาษบนภาพต้นฉบับ [TL, TR, BR, BL] (px) · null ถ้าไม่มี
    "width": 2618, "height": 3781         // ขนาดภาพต้นฉบับ
  },

  "cells": {                           // ② หาช่อง
    "box": { "x": 0.18, "y": 0.39, "w": 0.70, "h": 0.55 } // กรอบตารางคำตอบ (สัดส่วน 0–1 ของภาพที่ปรับแล้ว)
  },

  "reads": [                           // ③ อ่านตัวอักษร — 20 แถว × 20 ช่อง
    [ { "char": "C", "conf": 0.97, "cls": "char" }, ... ],
    ...
  ]
  // cls:  "char" = ตัวอักษรปกติ · "empty" = ช่องว่าง · "crossed" = ขีดฆ่า (ไม่นับ)
  // char: "A"–"Z" หรือ "" (ช่องว่าง)
  // conf: ความมั่นใจ 0–1 · ต่ำกว่า 0.55 → หน้า app ขึ้น "รอครูตรวจ"
}
```

### ฟิลด์เสริม (มีก็ดี — หน้า app จะใช้ถ้ามี)

```jsonc
{
  "subject_id": "89033467",
  "school_id": "610123456789",
  "question_set": 1,                   // วงกลมชุดกระดาษคำถาม 1–3 (null ถ้าไม่ได้ฝน)
  "page": 1,                           // วงกลมหน้ากระดาษคำตอบ 1–4

  "images": {                          // ภาพ before–after (ใช้ในหน้า app และสไลด์)
    "rectified": "data:image/jpeg;base64,...",   // ภาพหลังตัดขอบ/ดัดระนาบ
    "overlay":   "data:image/jpeg;base64,..."    // ภาพที่ตีกรอบช่อง (เขียว = ตัวอักษร, แดง = ขีดฆ่า)
  },

  "quality": {                         // เตือนผู้ใช้ว่าภาพอาจมีปัญหา
    "markers_found": 3,                // สี่เหลี่ยมดำที่เจอ (เต็ม 3)
    "timing_bars": [20, 20],           // ขีดดำซ้าย/ขวาที่เจอ (เต็ม 20)
    "warnings": []                     // ข้อความเตือนภาษาไทย
  },

  "timing_ms": { "dewarp": 570, "grid": 900, "read": 700, "total": 2480 }  // เวลาแต่ละขั้น
}
```

## การให้คะแนน — อยู่ฝั่งหน้า app

หน้า app ต่อคำและให้คะแนนเองจาก `reads` (ฟังก์ชัน `rowToWord` / `gradeRow` ใน `pipeline.js`)
เพราะครูแก้ช่องได้ แล้วคะแนนต้องคำนวณใหม่ทันที — โมเดลจึง**ส่งแค่ผลอ่านทีละช่อง** ไม่ต้องส่งคะแนน

เกณฑ์ปัจจุบัน: ข้ามช่องว่างและช่องขีดฆ่า แล้วต่อตัวที่เหลือ · พิมพ์เล็กนับเป็นพิมพ์ใหญ่ · ไม่ตอบ = ผิด
(รายละเอียด: [README หลัก ส่วนที่ 4](../README.md))

> ⚠️ โค้ดโมเดลปัจจุบันมีขั้น "Top-3 Lexicon Refinement" ที่ใช้คำในเฉลยช่วยแก้คำที่อ่านได้
> ถ้าจะใช้ ให้ส่งผลแยกจาก `reads` (เช่น `questions[].word`) และระบุให้ชัดตอนรายงานความแม่นยำ
> เพราะตัวเลขจะสูงกว่าความแม่นยำการอ่านจริง
