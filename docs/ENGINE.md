# Engine — ข้อตกลงระหว่างหน้า app กับโมเดล

โมเดล**รันในเบราว์เซอร์** (ไม่มี server) หน้า app เรียกโมเดลผ่านจุดเดียวคือ `Pipeline.run()` ใน
[`apps/js/pipeline.js`](../apps/js/pipeline.js) — **ผลที่ส่งกลับต้องเป็นรูปแบบในเอกสารนี้** หน้า app จะได้ไม่ต้องแก้

> สถานะ: **v0.2** — มี engine จริงแล้ว (Pyodide + ONNX, ดู [apps/README.md](../apps/README.md)) · โหมดจำลองยังเลือกได้ในหน้าตั้งค่า
> ถ้าทีมโมเดลจะเปลี่ยนชื่อ/ความหมายฟิลด์ ให้แก้ไฟล์นี้, `apps/engine/examer_engine.py` และ `pipeline.js` ใน PR เดียวกัน

## engine ที่ใช้ตอนนี้ (เสนอ — รอทีมยืนยัน)
- ①② ตัดขอบ/หาช่อง: โค้ด Python เดิมของ repo โมเดล รันด้วย Pyodide + OpenCV (ดึงจาก repo โมเดลตาม commit ที่ปักไว้ใน `apps/js/engine.js`)
- ③ อ่านตัวอักษร/ตัวเลข/ขีดฆ่า: `.pt` 3 ตัวแปลงเป็น ONNX (`apps/engine/models/`) รันด้วย onnxruntime-web
- ผลตรงกับ PyTorch 3,193/3,200 ช่องบน `data/Test` — ส่วนที่ต่างมาจาก OpenCV คนละเวอร์ชัน (Pyodide มี 4.9) → **ทีมโมเดลควรวัดผลด้วย OpenCV 4.9 ด้วย**
- ทีมโมเดลแก้โค้ด/เทรนใหม่ → อัปเดต commit ใน `engine.js` และแปลง ONNX ใหม่

## เรียกใช้

```js
const result = await Pipeline.run(file, exam);
// file: File    ภาพกระดาษคำตอบ (JPG/PNG)
// exam: object  การสอบ (โหมดจำลองใช้เฉลยในนี้สร้างข้อมูลตัวอย่าง · engine จริงไม่ใช้เฉลย)
```

ถ้าตรวจไม่ได้ให้ `throw new Error("ข้อความภาษาไทย")` — หน้า app จะแสดงข้อความนั้นให้ผู้ใช้
เช่น `"หาสี่เหลี่ยมดำ 3 มุมของกระดาษไม่ครบ — ถ่ายใหม่ให้เห็นทั้งแผ่น"`

## ผลที่ส่งกลับ (`Result`)

### ฟิลด์ที่หน้า app ใช้อยู่แล้ว (ต้องมี)

```jsonc
{
  "student_id": "67160328",            // อ่านจากช่องรหัสสีม่วง ("" ถ้าไม่ได้เขียน)

  "dewarp": {                          // ① ตัดขอบ/ปรับภาพ
    "corners": [[x,y],[x,y],[x,y],[x,y]], // มุมกระดาษบนภาพต้นฉบับ [TL, TR, BR, BL] (px) · null ถ้าไม่มี
    "width": 2618, "height": 3781         // ขนาดภาพต้นฉบับ
  },

  "cells": {                           // ② หาช่อง
    "box": { "x": 0.18, "y": 0.39, "w": 0.70, "h": 0.55 } // กรอบตารางคำตอบ (สัดส่วน 0–1 ของภาพที่ปรับแล้ว)
  },

  "reads": [                           // ③ อ่านตัวอักษร — 20 แถว × 20 ช่อง
    [ { "char": "C", "conf": 0.97, "cls": "char",
        "bbox": [x1, y1, x2, y2],           // กรอบช่องบนภาพที่ปรับแล้ว (สัดส่วน 0–1) — ใช้ตัดภาพช่องให้ครูดู
        "top3": [["C", 0.97], ["G", 0.02], ["O", 0.01]] }, ... ],
    ...
  ]
  // cls:  "char" = ตัวอักษรปกติ · "empty" = ช่องว่าง · "crossed" = ขีดฆ่า (ไม่นับ)
  // char: "A"–"Z" หรือ "" (ช่องว่าง)
  // conf: ความมั่นใจ 0–1 = min(ความน่าจะเป็นตัวอักษรนี้, ความน่าจะเป็นว่าเป็นช่องตัวอักษร) · ต่ำกว่าค่าในตั้งค่า (เริ่มต้น 0.6) → "รอครูตรวจทาน"
}
```

## การให้คะแนน — อยู่ฝั่งหน้า app

หน้า app ต่อคำและให้คะแนนเองจาก `reads` (ฟังก์ชัน `rowToWord` / `gradeRow` ใน `pipeline.js`)
เพราะครูแก้ช่องได้ แล้วคะแนนต้องคำนวณใหม่ทันที — โมเดลจึง**ส่งแค่ผลอ่านทีละช่อง** ไม่ต้องส่งคะแนน

เกณฑ์ปัจจุบัน: ข้ามช่องว่างและช่องขีดฆ่า แล้วต่อตัวที่เหลือ · พิมพ์เล็กนับเป็นพิมพ์ใหญ่ · ไม่ตอบ = ผิด
(รายละเอียด: [README หลัก ส่วนที่ 4](../README.md))

> ⚠️ โค้ดโมเดลปัจจุบันมีขั้น "Top-3 Lexicon Refinement" ที่ใช้คำในเฉลยช่วยแก้คำที่อ่านได้
> ถ้าจะใช้ ให้ส่งผลแยกจาก `reads` (เช่น `questions[].word`) และระบุให้ชัดตอนรายงานความแม่นยำ
> เพราะตัวเลขจะสูงกว่าความแม่นยำการอ่านจริง
> engine ในเบราว์เซอร์ตอนนี้ **ไม่ใช้** ขั้นนี้ (ส่งผลอ่าน Top-1 ตรงๆ + `top3` ให้ครูเลือกตอนตรวจทาน)
