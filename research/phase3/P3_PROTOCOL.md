## 3. ระบบที่วัด (ทั้งสายงาน ไม่ใช้ป้ายช่วย)
1. Phase 1 v3 (ล็อก 12b4652b…) → หน้าสแกนสี
2. Phase 2A (ล็อก cddc528e…) → เส้นแถว/เส้นตั้ง
3. Phase 3A: หมึกจากสี — มาสก์เส้นที่ track ได้ + likelihood ratio สี (เทา × blueness) เรียนรายแผ่น → แยกตัวอักษรรายแถว (connected components จัดกลุ่มตามแนว x) → ภาพ 48×48
4. Phase 3B: CNN 26 คลาส (A–Z) · เทรนด้วย Horizontal Train (splits_v2) + ตัวอักษรจาก train ทับเส้น (เฉพาะแถวที่แยกได้ 13 ตัวพอดี) + เสริมข้อมูลจำลองเส้นทับ
- หมายเหตุ: แผ่นชนิดนี้อ่านเป็น "ลำดับตัวอักษรต่อแถว" เพราะตัวที่ทับเส้นตั้งคร่อม 2 ช่อง จึงไม่ผ่าน 2B รายช่อง

## 4. ตัวชี้วัด
- **CAR** = 1 − Σ edit distance(สตริงที่อ่านได้, สตริงจริง) / Σ จำนวนตัวจริง — ต่อแถว รวมทุกแถว (การแยกผิด เกิน/ขาด นับด้วย)
- **WAR (แถว)** = สัดส่วนแถวที่อ่านถูกทั้ง 13 ตัว
- แยกตามชนิดทับเส้น: บน / ล่าง / ซ้าย / เส้นตั้ง · รายงาน 95% CI แบบ Wilson (CAR นับต่อตัวอักษร)
- ตัวเทียบ (baseline): โมเดลเดิมที่เทรนเฉพาะ Horizontal (ไม่มีข้อมูลทับเส้นจริง) บนสายงานเดียวกัน

## 5. เกณฑ์ผ่าน (Test, ล็อกก่อนเห็นผล)
- G1: CAR (ทั้งหมด) ≥ 90%
- G2: CAR สูงกว่า baseline อย่างมีนัย (CI ไม่ทับกัน หรือ McNemar p < 0.05 บนตัวอักษรที่จับคู่ได้)
- G3: ทุกชนิดทับเส้น CAR ≥ 85%
- WAR รายงานเป็นข้อมูลประกอบ (ไม่ใช่เกณฑ์ผ่าน เพราะแถวละ 13 ตัว ผิด 1 ตัว = ทั้งแถวผิด)

## 6. ขั้นตอน
1. พัฒนาบน train เท่านั้น · ตัวเลขระหว่างพัฒนา = แบ่งกลุ่มคนเขียนภายใน train (A = IMG_80xx · B = IMG_97xx) เทรนกลุ่มหนึ่ง ทดสอบอีกกลุ่ม
2. ถามผู้ใช้ก่อนใช้ val → ใช้เลือกค่า (epoch / ตัวเลือกที่เตรียมไว้) ครั้งเดียว
3. ล็อกโค้ด + โมเดลด้วย sha256 (LOCK_P3.md) → ถามผู้ใช้ → รัน test ครั้งเดียว → ไม่แก้หลังเห็นผล
