## ตัวชี้วัด (ต่อหน้าสแกน)
1. หาแถวเจอ: แถวที่ตรวจพบ จับคู่ GT ด้วย IoU กรอบแถว ≥ 0.5 → recall แถว
2. นับช่องถูก: แถวที่จับคู่ได้ มีจำนวนช่อง = 20 → % ของแถว
3. ความแม่นกรอบช่อง: จับคู่ช่องกับ GT ตาม IoU → P / R / F1 ที่ IoU 0.6 · 0.7 · 0.8 · 0.9 และ WAvg F1 = Σ(t·F1_t)/Σt (แบบ CascadeTabNet [3])
4. crop สะอาด (เฉพาะกระดาษเปล่า): crop มีจุดมืด (เทา < 128) ≤ 0.2% ของพื้นที่ → ไม่ติดเส้นกรอบ
5. หน้าถูกทั้งหน้า: 20 แถว × 20 ช่อง ครบและถูก

## แก้ไขก่อนรัน Test (2026-10-22 · ทำบน Dev เท่านั้น · Test ยังไม่ถูกแตะ)
**ก. GT แม่แบบดิจิทัลไม่ตรงกับกระดาษที่พิมพ์จริง** — วัดกึ่งกลางเส้นจริงบนกระดาษเปล่า Dev 50 แผ่น (โปรไฟล์ความเข้ม ไม่ใช้ detector · p2a_measure_gt.py)
พบว่าตารางที่พิมพ์ย่อจากแบบดิจิทัล: แถว 1 ต่ำกว่าแบบ +6 px · แถว 20 สูงกว่าแบบ −4 px (เครื่องพิมพ์ย่อ ~0.5%) · 50 แผ่นสอดคล้องกัน (IQR ≤ 2.75 px)
→ GT ใหม่ = **ตารางที่พิมพ์จริง** (p2a_gt_printed.json) · ช่อง = ภายในเส้น (กึ่งกลางเส้น ± 3 px) นิยามเดียวกันทั้ง GT และ detector
**ข. แต่ละแผ่นคลาดจากตารางคงที่ได้ ±5 px (ความคลาดของ Phase 1 ≤ 8 px + กระดาษโค้ง)** → IoU 0.9 ของช่อง 77 px ไวต่อ 4–5 px
→ GT หลัก = **GT รายแผ่น** (p2a_gt_sheet.py): ฟิตตารางที่พิมพ์จริงเข้ากับเส้นในแผ่นนั้นด้วยโปรไฟล์ความเข้ม (คนละวิธีกับ detector)
→ แถวที่ detector กับ GT รายแผ่นไม่ตรงกัน (IoU < 0.9) = "ตั้งธง" → ตรวจด้วยตาทุกแถว แล้วรายงานจำนวน (ตัวเลขด่านใช้ค่าดิบ ไม่ปรับตามการตรวจด้วยตา)
→ รายงานเทียบตารางคงที่ด้วย (ข้อมูลประกอบ: รวมความคลาดของ Phase 1)
**ค. crop:** หดเข้า 7 px จากขอบในเส้น (Dev: 5 px → สะอาด 99.04% เพราะเส้นเอียงแตะขอบ · 7 px → 100%)
