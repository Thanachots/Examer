## 1. โปรเจคคืออะไร

- **โจทย์:** ระบบรับภาพกระดาษคำตอบ (Template 2) แล้วอ่านลายมือและให้คะแนนอัตโนมัติ
- **ข้อสอบเป็นข้อเขียน:** 20 ข้อ × 20 ช่อง = 400 ช่อง เขียนตัวอักษรภาษาอังกฤษ **A–Z ช่องละ 1 ตัว**
- **Workflow:** ภาพเข้า → ตัดขอบ/ปรับภาพ → จับช่อง → อ่านตัวอักษร → เทียบเฉลยและให้คะแนน → ผลออก (JSON/CSV + รายการให้ครูตรวจซ้ำ)
- **ปลายทาง:** Mobile App — ตอนนี้ทำเป็น **Web (ต้นแบบ)** ก่อนเพราะเวลาจำกัด และใช้ web เป็นแหล่งภาพ/วิดีโอ before–after ในการนำเสนอ
- **บริบทการนำเสนอ:** ทำเหมือน startup รายงานความคืบหน้าให้นักลงทุน (มีหลายกลุ่ม นักลงทุนเลือก 1 กลุ่ม) — เวลา **15 นาที**

### ส่วนประกอบของ Template 2

| ส่วนบนกระดาษ | รายละเอียด | ใช้ทำอะไร |
|---|---|---|
| สี่เหลี่ยมดำ 3 จุด | ล่างซ้าย, ล่างขวา, กล่อง "2" ขวาบน | ปรับภาพให้ตรง + เช็คกลับหัว |
| ขีดดำซ้าย–ขวา | 40 จุด (แถวละ 2) | ระบุตำแหน่งข้อ 1–20 |
| ตารางคำตอบ | 20 × 20 = 400 ช่อง | ช่องละ 1 ตัวอักษร |
| ช่องรหัส | ประจำตัว / วิชา / สถานศึกษา | ระบุตัวนักเรียน (ตัวเลขเขียนมือ) |
| วงกลมเลือก | ชุดกระดาษคำถาม 1–3, หน้ากระดาษคำตอบ 1–4 | เลือกเฉลยให้ถูกชุด |
| ช่องเขียนชื่อ | ชื่อ, วิชา, ปีการศึกษา, ห้อง, วันที่ | ไม่อ่าน (ใช้รหัสแทน) |

ข้อสังเกต: ไม่มี landmark ด้านบน/ล่างสำหรับคอลัมน์ → หาคอลัมน์จากเส้นตารางแทน

## 2. Paper ที่ใช้ และใช้ส่วนไหน

| Paper | เนื้อหา | บทบาทในโปรเจค |
|---|---|---|
| **CLA** – Yookwan et al., SNPD 2025 | OMR จากกล้องมือถือ: Canny → contour → homography, YOLOv8, template matching, Cross-Linear Area | ⭐ แกนหลักส่วน **ตัดขอบ + จับช่อง** |
| **OMRNet** – MTAP 2024 | MobileNetV2 จำแนกช่องเป็น confirmed / crossed-out / empty | ⭐ โครงสร้างโมเดล **อ่านตัวอักษร** + แนวคิดคลาสขีดฆ่า |
| **TrOCR** – AAAI 2023 | Transformer อ่านลายมือทั้งบรรทัด | Baseline เปรียบเทียบ + เทคนิค augmentation |
| **DocUNet** – CVPR 2018 | Stacked U-Net คลี่กระดาษยับ | ใช้เฉพาะถ้ากระดาษยับ (ไม่จำเป็น) |
| **CascadeTabNet** – CVPRW 2020 | ตรวจจับตาราง | ใช้แค่แนวคิดหาเส้นตาราง |

### ตัวเลขสำคัญจาก paper (ตรวจสอบแล้ว)
- **CLA:** Structural field detection 98.4%, Answer area 99.2%, Landmark detection 97.5%, OMR 96.8% — 1.35 วินาที/แผ่นบนมือถือระดับกลาง (ไม่ระบุค่า threshold)
- **OMRNet:** Accuracy เฉลี่ย 95.96% (5-fold), quantize เหลือ 3 MB (ลดลง 0.40%)
- **TrOCR:** Small 62M / Base 334M / Large 558M params; CER บน IAM = 4.22 / 3.42 / 2.89

### ข้อมูลเชิงปัญหาจาก paper (ใช้ในหน้า Market ได้)
- **CLA:** OMR แบบเดิมต้องใช้เครื่องสแกนเฉพาะ + กระดาษมาตรฐาน ต้นทุนสูง เข้าถึงยากในที่ทรัพยากรจำกัด; สมาร์ทโฟนทำให้เข้าถึงได้กว้างขึ้น
- **OMRNet:** OMR ทั่วไปไม่รองรับการขีดฆ่าแก้คำตอบ และรอยเปื้อน/การวางเบี้ยวทำให้อ่านผิด

## 3. โมเดลอ่านตัวอักษร (ดัดแปลงจาก OMRNet)

```
Input 224×224×3
 → MobileNetV2 (pretrained ImageNet, feature extractor)
 → Flatten
 → FC 640 → Dropout 0.25
 → FC 320 → Dropout 0.25
 → FC 160 → Dropout 0.25
 → Softmax 28 คลาส (A–Z + EMPTY + CROSSED)
```

| ค่า | ตาม OMRNet | สิ่งที่เราปรับ |
|---|---|---|
| Input | 224×224×3, bilinear, /255 | ภาพ grayscale → copy เป็น 3 channel |
| Activation | ReLU, PFLU, FPFLU | ใช้ ReLU ได้ถ้าไม่อยากเขียน PFLU เอง |
| Output | 3 คลาส | **28 คลาส** |
| Batch / Epochs | 32 / 10 | เหมือนเดิม |
| Loss | Sparse categorical cross-entropy | เหมือนเดิม |
| Optimizer | Adam lr 0.001, β1 0.9, β2 0.999, ε 1e-7 | เหมือนเดิม |
| Augmentation | translation, rotation, flip | **ตัด flip ออก** (ตัวอักษรพลิกแล้วเป็นตัวอื่น) ใช้ของ TrOCR: rotation ±10°, Gaussian blur, dilation, erosion, downscaling, underlining |
| Validation | 20% / 5-fold | แบ่ง fold **ตามคนเขียน** (10 คน → 5 fold × 2 คน) |
| Pretrain | ImageNet | + **EMNIST Letters** ก่อน แล้ว fine-tune ลายมือจริง (ส่วนที่เราเพิ่มเอง) |

**ทางเปรียบเทียบ:** TrOCR-small อ่านทั้งแถว (input 384×384) — หนักกว่า, เส้นตารางรบกวน, ไม่รู้ว่าตัวอักษรอยู่ช่องไหน → ใช้เป็น baseline

**สิ่งที่ต้องหาเองจากการทดลอง:** threshold สัดส่วนหมึก, ขนาดการหดขอบตอนตัดช่อง (ประมาณ 10–15%)

**คู่ตัวอักษรที่น่าจะสับสน:** O/D/Q, U/V, I/J/L, C/G, M/N → ตรวจด้วย confusion matrix

## 4. เกณฑ์การตรวจของระบบ

| กรณี | ระบบตรวจจับยังไง | เกณฑ์ |
|---|---|---|
| เขียนปกติ 1 ตัว/ช่อง | CNN confidence สูง | ใช้ผลที่อ่านได้ |
| ช่องว่าง | สัดส่วนหมึกต่ำ / คลาส EMPTY | ข้ามช่อง |
| ขีดฆ่า | คลาส CROSSED | ไม่นับ ใช้ตัวที่เหลือต่อกัน เช่น C A ~~X~~ T → CAT |
| เขียนล้นช่อง | หมึกแตะขอบมากผิดปกติ | ขยายกรอบตัด ถ้าทับช่องข้างเคียง → ครูตรวจ |
| อ่านไม่ออก / 2 ตัวในช่อง | confidence ต่ำ | ส่งครูตรวจซ้ำ |
| ตัวพิมพ์เล็ก | เทรนรวมพิมพ์เล็ก-ใหญ่ | นับเหมือนพิมพ์ใหญ่ *(ในสไลด์รอบแรกกำหนดว่าต้องพิมพ์ใหญ่เท่านั้น — เลือกให้ตรงกัน)* |
| ไม่ได้ตอบทั้งข้อ | ทุกช่องว่าง | 0 คะแนน |
| คำยาว/สั้นกว่าเฉลย | เทียบความยาว | ผิด |
| เว้นช่องกลางคำ / เริ่มไม่ใช่ช่องแรก | — | **[ต้องตกลงกัน]** |

**ข้อควรรู้:** ถ้าอ่านถูกตัวละ 95% คำ 10 ตัวจะถูกทั้งคำแค่ ≈ 0.95¹⁰ ≈ 60% → ต้องมีระบบให้ครูตรวจซ้ำ และอาจใช้เฉลยช่วยคำนวณความน่าจะเป็น

## 6. Dataset

- **300 แผ่น, 10 คน** — สุดท้ายใช้ **3 แบบ**:

| แบบ | วิธีเขียน | ใช้ทำอะไร | จำนวน |
|---|---|---|---|
| Horizontal | A–Z วนแนวนอนจนเต็ม 400 ช่อง | เทรนโมเดล | [ ] |
| Words | เขียนเป็นคำ ถูกทุกข้อ | วัด Word-level Accuracy | [ ] |
| Edge | กรณีพิเศษ: ขีดฆ่า, ล้นช่อง, 2 ตัวในช่อง, พิมพ์เล็ก, ดินสอจาง, เว้นช่อง, ตัวเอียง ฯลฯ | ทดสอบเกณฑ์การตรวจ | [ ] |

- **Label อัตโนมัติ (Horizontal):** ลำดับช่อง i = (ข้อ−1)×20 + (ช่อง−1) → label = ตัวอักษรลำดับที่ (i mod 26)
- **Words / Edge:** ต้องจด ground truth ตอนเขียน (สิ่งที่เขียนจริง + คำตอบสุดท้าย)
- **ถ่ายหลายสภาพ:** scan / ถ่ายตรง / ถ่ายเอียง / แสงน้อย
- **แบ่ง train/test ตามคนเขียน** (เช่น คน 1–8 เทรน, 9–10 ทดสอบ) — ห้ามสุ่มรายช่อง

ชื่อไฟล์แนะนำ: `T2_{แบบ}_{คนเขียน}_{แผ่นที่}_{สภาพ}.jpg` + `labels.csv` (file_id, row, col, label) + `answers.csv`

(แบบที่เคยคิดไว้แต่ไม่ใช้: Vertical, Row, Column, Mixed, Exam)
